# Навантажувальне тестування

Locust виконує сценарій «один запис, дев'ять читань» на одного віртуального користувача. Запис — створення callback-заявки, єдиний публічний write endpoint цього API. Дев'ять читань — списки товарів із різними параметрами та деталі товару. Читання щойно створеної заявки неможливе в цьому профілі, бо GET callback requests вимагає адміністративної авторизації. Сутності автора в каталозі немає; це адаптація профілю до реального API, яку треба пояснити на захисті.

Фази за замовчуванням: плавне наростання від 0 до 40 користувачів за 2,5 хвилини, 5,5 хвилини плато, спад за 2 хвилини. Загальна тривалість — **10 хвилин**. Користувач робить паузу 0,5–1,5 секунди між запитами. Змінні `LOADTEST_MAX_USERS` і `LOADTEST_SPAWN_RATE` дають змогу налаштувати інтенсивність. 40 users — початкова оцінка; якщо CPU не перетинає 60%, збільшуйте її невеликими кроками, не перевищуючи ECS max capacity 4.

Запуск із кореня репозиторію:

```powershell
$env:LOADTEST_MAX_USERS = "40"
$env:LOADTEST_SPAWN_RATE = "4"
uv run --with locust locust -f .\loadtest\locustfile.py --host https://api.auto-catalog.app --headless --csv .\docs\results\loadtest --csv-full-history --html .\docs\results\loadtest.html
```

Запити POST записуються у PostgreSQL. Запускайте лише на тестовому середовищі або з дозволом власника даних. Після тесту перевірте ECS desired/running count; scale-in може зайняти cooldown 300 секунд і додатковий час стабілізації.

## Результат попереднього прогону

Прогін 2026-11-11 завершився, але його профіль був старішою версією (10 незалежно зважених GET-задач і один POST), а тривалість становила близько 9,5 хвилин. Це baseline, а не доказ виконання оновленого сценарію.

| Запити | Помилки | Частка помилок | RPS | p50 | p95 | p99 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 363 | 1 | 0,0061% | 28,77 | 38 мс | 160 мс | 360 мс |

Єдиний збій: `GET products sort asc` отримав HTTP 502 о 13:50:45 UTC. Locust завершив усі фази й повернув exit code 1 через цей невдалий запит. CSV/HTML — у `docs/results/`. Новий звіт потрібно додати після деплою оновленого сценарію; не підміняйте його цими baseline цифрами.
